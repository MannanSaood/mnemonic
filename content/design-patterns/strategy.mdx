## [concept] Strategy

**Put each way of doing one step behind a shared <Term id="interface">interface</Term>, and let the caller choose which one to plug in.**

The code that *uses* the step should not need to know how many ways there are to do it, or which one it was given.

<Depth level={2}>
Three roles do the work. The <Term id="context-role">context</Term> (`Uploader`) holds a strategy and calls it. The **strategy** is the step, named as a type. Each **concrete strategy** is one way of doing the step. A fourth party, the **client**, picks one and hands it in; usually that is `main` or the config loader. Handing it in is <Term id="dependency-injection">dependency injection</Term>.
</Depth>

<Depth level={3}>
The 1994 *Design Patterns* catalogue files Strategy under behavioral patterns, and frames it as an alternative to subclassing: instead of a subclass per algorithm, the algorithm becomes an object of its own. It also names the costs. The client has to know the strategies exist in order to choose one, and every strategy receives the same inputs, even the ones it ignores. In languages where functions are values, a one-method strategy usually shrinks to a function.
</Depth>

## [problem] A branch that keeps growing

A service uploads build artifacts to object storage and compresses each file first. The codec comes from config. The code works, and it is tested.

Read it once. The list of codecs lives in three places: the branch in the upload method, the config check, and the header mapping.

<Depth level={2}>
Each branch is a separate algorithm sharing one function. To test zstd on its own, you still build a whole Uploader and go through the branch.
</Depth>

<Depth level={3}>
Nothing here is wrong yet. Two codecs behind an `if` would be perfectly fine. The problem is the rate of change: each new codec edits the same three places, and each edit can break the codecs that already work.
</Depth>

## [pain] Then a change request arrives

**Change request:** the web-assets bucket needs Brotli. Browsers accept `Content-Encoding: br`, and Brotli compresses text better than gzip.

The marked lines must change. None of them is about how Brotli works. They are bookkeeping, spread across three files.

<Depth level={2}>
Miss one and the code still compiles. The config check rejects `"brotli"`, or the header says `brotli` instead of `br`, and you find out from a browser in production.
</Depth>

<Depth level={3}>
The branches also share one test surface. A change to the Brotli branch re-runs the tests of every other codec, and a mistake in it can break them.
</Depth>

## [morph] Turn each branch into its own strategy

Drag the slider. The branch becomes one interface, and each case moves out into its own small unit: a type, or in Python often just a function.

Hover a box in the diagram to see its code.

<Depth level={2}>
Uploader now depends on one small set of methods instead of on the list of codecs. Each codec can be tested on its own, with a fixed input. New codecs extend the system without editing it: the <Term id="open-closed">open/closed principle</Term>.
</Depth>

<Depth level={3}>
<Lang only="go">Go interfaces are satisfied implicitly. `Zstd` never says it implements `Compressor`; having the two methods is enough, and the compiler checks it where a `Zstd` is assigned to a `Compressor`.</Lang>
<Lang only="python">Nothing is declared at all. Any callable that takes bytes and returns bytes fits, and the type hint is checked only by tools such as mypy.</Lang>
<Lang only="typescript">TypeScript uses <Term id="structural-typing">structural typing</Term>: a `Zstd` fits `Compressor` because it has the right shape, with or without `implements`.</Lang>
<Lang only="rust">Each codec opts in explicitly with `impl Compressor for Zstd`, and the compiler checks the method signatures there.</Lang>
</Depth>

## [walk] Follow one upload

One call through the design, start to finish. Step through it with the numbered buttons.

<Depth level={3}>
<Lang only="go">A call through an interface loads the method's address from the <Term id="itab">itab</Term> and makes an indirect call. That costs a few nanoseconds and usually prevents inlining. For a compressor that touches every byte, the cost is noise; in a tight inner loop it can matter.</Lang>
<Lang only="python">`self.compress(data)` is an attribute lookup on the instance followed by a call. There is no interface table: whatever object is stored there is called, and a wrong one fails only when it runs.</Lang>
<Lang only="typescript">The interface exists only at compile time. At runtime `this.c.compress` is a property lookup on the object; V8's inline caches keep it fast while a call site only ever sees one or two kinds of object.</Lang>
<Lang only="rust">With `Uploader<C>`, the compiler makes one copy of `upload` per codec (<Term id="monomorphisation">monomorphisation</Term>) and can inline `compress`. `Box<dyn Compressor>` trades that for a single copy and a vtable call: <Term id="dynamic-dispatch">dynamic dispatch</Term>.</Lang>
</Depth>

## [again] Brotli, the second time

The same Brotli request, after the refactor. You add one new strategy. Nothing that already exists changes, so nothing that already works can break.

<Depth level={2}>
One line of wiring remains: whatever turns the config string `"brotli"` into the new strategy. Keep that in one place, such as a map from names to constructors, and it stays one line.
</Depth>

<Depth level={3}>
Tests follow the same split. The new codec gets its own test with a fixed input. Uploader's tests use a fake strategy that records what it was given, and they never change when a codec is added.
</Depth>

## [reference]

### When the strategy is just a function

If a strategy has one method and no state, most languages let you pass a function instead of defining a type: `sort.Slice` in Go, `key=` in Python, a comparator in TypeScript, a closure in Rust. Start there. Move to an interface or trait when the strategy needs a second method (here, `Encoding`) or carries configuration such as a compression level.
