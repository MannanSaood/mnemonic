    - role: Object

    - role: Reference count
      example: "`sys.getrefcount(x)`"
      job: Counts the references to an object. At zero, CPython frees it at once.
    - role: Cycle collector
      example: "`gc.collect()`"
      job: Frees groups of objects that refer only to each other.
    - role: Weak reference
      example: "`weakref.WeakMethod`, `WeakValueDictionary`"
      job: Refers to an object without keeping it alive.
  useWhen:
    - A function has a list, dict or set as a parameter default.
    - You build nested lists with `*`, or store a caller's list in an object.
    - An object stores a callback, bound method or parent pointer that leads back to itself.
    - Memory grows in a long-running process although everything is "deleted".
  avoidWhen:
    - The values are immutable (str, int, tuples of immutables, frozen dataclasses). Sharing them is safe, and copying wastes time.
  tradeoffs:
    - Copying at a boundary (`list(cc)`) costs an allocation per call but removes a whole class of aliasing bugs.
    - Weak references can go dead at any moment, so every use must check for `None`.
    - "`gc.disable()` and `gc.freeze()` trade collector pauses for memory: fine for short-lived workers, dangerous with cycles."
  lookalikes:
    - name: Call by reference
      how: The callee could rebind the caller's variable. Python cannot; it can only change the shared object.
    - name: Call by value
      how: The callee gets a copy. Python never copies an argument.
    - name: copy.deepcopy
      how: Copies everything reachable. Needed only when nested mutable objects must be independent.

## [concept] Names, references, mutability, recycling

**A Python variable is a name bound to an object. Assignment, arguments and defaults never copy: they add a reference. CPython frees an object the moment its last reference goes, unless it is part of a cycle.**

Two names can refer to one list, and a change made through one is seen through the other. That is <Term id="aliasing">aliasing</Term>, and in Python it is the default.

<Depth level={2}>
Three rules cover most bugs. Assignment binds a name; it does not copy. Arguments are passed by sharing (<Term id="call-by-sharing">call by sharing</Term>): the function gets a new name for your object. Default values are evaluated once, when `def` runs, so a <Term id="mutable-default-argument">mutable default argument</Term> is one object shared by every call. `is` compares identity and `==` compares value; they agree only by accident.
</Depth>

<Depth level={3}>
In CPython every object header holds a <Term id="reference-count">reference count</Term>. Binding a name or storing the object in a container adds one; unbinding removes one; at zero the object's deallocator runs immediately. Objects that only refer to each other never reach zero, so a separate <Term id="cycle-collector">cycle collector</Term> looks for them among container objects (lists, dicts, instances, functions). Strings and ints cannot form cycles and are not tracked by it.
</Depth>

## [problem] Who gets this invoice

A billing service emails each invoice to the customer. A helper builds the recipient list, with an optional `cc` list for the callers that need one. It works, and it is tested: each test sends one invoice and checks one address.

Read it with the model most people start with: a variable is a box that holds a value, and `cc=[]` means "an empty list each time".

<Depth level={2}>
The default list is made once. The first invoice appends to it, the second appends to the same list, and so on. Tests pass because each test process sends a single invoice, or because the test calls `recipients` with an explicit `cc`.
</Depth>

<Depth level={3}>
<Lang only="python">`recipients.__defaults__` holds the list. You can watch it grow in a REPL: call the function twice and print `recipients.__defaults__`.</Lang>
<Lang only="go">`append` returns a slice that shares `alwaysCC`'s backing array whenever there is spare capacity. Every queued `Email` gets a `To` that points into the same array, at index 1.</Lang>
<Lang only="typescript">The default is evaluated per call, but `ALWAYS_CC` is one module-level array, and `push` changes it in place.</Lang>
<Lang only="rust">`&mut self` lets `recipients` change `self.cc`, and it does, on every call. The compiler allows it because it was asked for.</Lang>
</Depth>

## [pain] Then a change request arrives

**Change request:** CC each account's billing contacts on its invoices.

The marked line goes into the shared list too. In production the process runs for days. Invoice 500 goes to 500 customers, each with every earlier account's billing contacts in CC. The incident is a data leak, not a crash.

<Depth level={2}>
The naive model cannot explain it: the code never shares anything on purpose. The sharing is in the semantics. The list on the `def` line is one object, created at import, and every call that leaves `cc` out appends to it. Restarting the service "fixes" it until the list grows again.
</Depth>

<Depth level={3}>
<Lang only="python">The same rule applies to dict and set defaults, to class attributes such as `tags = []` on a class body (one list shared by every instance), and to `[[]] * n`, which repeats one reference n times.</Lang>
<Lang only="go">The Go symptom is different: every queued email is sent to the last customer queued, because each `To` slice reads the same array slot, which the most recent `append` overwrote.</Lang>
<Lang only="typescript">The TypeScript symptom matches Python's. Any module-level array or object used as a default, or as a starting value that gets mutated, is shared across requests.</Lang>
<Lang only="rust">Rust shows the same growth, but only because the signature asked for `&mut self`. A reviewer can see it; the borrow checker cannot know it was not meant.</Lang>
</Depth>

## [morph] From boxes that hold values to names that refer

Drag the slider. The picture of a fresh box per call gives way to what is really there: a function object holding one default list, names that refer to objects, and a reference count that frees each per-call list when the call is done.

The code morphs to make a new list inside the call, so nothing is shared between invoices.

Hover a box in the diagram to see its code.

<Depth level={2}>
`None` is the idiomatic default: it is immutable, so sharing it is harmless, and `cc is None` distinguishes "not given" from "given and empty". `list(cc)` also copies a caller's list, so `recipients` never changes something it was handed. Copy at the boundary where you start mutating.
</Depth>

<Depth level={3}>
<Lang only="python">`list(cc)` is a <Term id="shallow-copy">shallow copy</Term>: the new list holds references to the same email strings. That is safe because strings are immutable. A list of dicts would need each dict copied too, or a `copy.deepcopy`.</Lang>
<Lang only="go">`make([]string, 0, len(cc)+1)` gives the result its own array. `slices.Clone(cc)` followed by `append` does the same in one call.</Lang>
<Lang only="typescript">Typing the parameter as `readonly string[]` turns any future `push` on `cc` into a compile error, so the fix stays fixed.</Lang>
<Lang only="rust">With `&self`, the method cannot change `self.cc` at all. The clone makes the caller the owner of the result.</Lang>
</Depth>

## [lens] How each language meets it

All four languages share objects through references somewhere. They differ in where copies happen by default, whether defaults are re-evaluated, and what frees memory: reference counts, a tracing collector, or ownership.

### What frees an object in CPython

Reference counting frees almost everything, the moment the last reference goes. The cycle collector exists for the rest. It tracks container objects in three generations and runs when allocations minus deallocations pass a threshold (`gc.get_threshold()`). It copies each candidate's count, subtracts the references that come from other candidates, and anything still above zero is reachable from outside; what is left unreached is a cycle of garbage and is freed. Since 3.4, objects with `__del__` in a cycle are collected too.

A few details matter in practice. Since 3.12, `None`, `True`, small ints and some other objects are <Term id="immortal-object">immortal</Term>: their refcount is fixed and `sys.getrefcount` shows a huge number. Python 3.14.0 to 3.14.4 shipped an incremental collector, and 3.14.5 went back to the 3.13 generational one after reports of memory pressure. The free-threaded build uses biased reference counting and a non-generational collector that pauses all threads and scans the whole heap. `gc.freeze()` before `fork()` moves existing objects out of the collector's sight, so forked workers do not touch, and copy, their pages.
